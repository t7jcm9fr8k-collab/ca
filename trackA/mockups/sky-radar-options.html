HUD · SKY + RADAR

Four sky treatments, three radars

All four skies below carry the same 600-star field drifting on the 25° axis that is now in the app, so the only variable is what sits behind it. The radars are live — watch the motion, not the still.

1 · GALAXIES AND CLUSTERS

Every one of these rasterises once at launch and is then slid by the GPU, exactly like the existing star layers — so the cost difference between them is a few milliseconds at startup and nothing at all while running. Pick on how it looks, not what it costs.

A · PROCEDURAL SPIRAL

Two logarithmic arms, ~1,400 points, bright core falling off to nothing. Reads as an object with structure — the only option that actually looks like a galaxy at this size. And the only one that can look wrong: a spiral is a shape people recognise, so a bad one is noticeable in a way a soft blob never is.

B · SPRITE BLOB

Rotated elliptical gradients with a scatter of stars over the top. Suggests a distant galaxy without claiming to be one. Safe, fast, and honestly a little generic — it is what most sci-fi backgrounds actually use.

C · NEBULA BLOOM

Large irregular patches under the stars, in the layer your nebula already occupies. Cheapest to add — it is a change to a function that exists rather than a new one. "High def" is the one thing it will not be; it adds mood, not objects.

D · DENSE CLUSTERS

Three knots of 60–90 stars with a gaussian falloff, brighter and smaller than the field. Needs no new drawing code at all — same dots, different distribution. Reads as depth rather than as scenery, which suits an instrument better than a poster does.

They combine. D costs nothing and makes A or B look further away; C under either adds the colour. If you want one answer: A plus D — one spiral off-centre, three clusters elsewhere, nebula unchanged.

2 · DIAGNOSTICS RADAR

All three drive the same seven checks. The difference is when they move and what the motion claims — which matters more than it sounds, because a dial that spins while nothing is happening is an instrument that lies.

A · CONTINUOUS · ROWS LIGHT ON BEARING

The arm never stops. Each check brightens as the beam crosses its bearing, so the panel feels swept rather than listed. This is the one place a repeating animation earns it — a radar that stops is not a radar — but it is also a display link kept alive for as long as the tab is open. The 3D read is a 52° tilt on the dial only; the rows stay flat and legible.

B · SWEEP ONLY WHILE CHECKING
IDLE

Turns twice, resolves each row as it passes, then rests. Motion means work is happening — which is true here, since diagnostics genuinely re-check on launch and on returning to the front. Costs nothing at idle. Less cinematic, and it is the version that matches how the rest of this app already behaves.

C · LINE SWEEP ONLY — no dial

The pass already built, moved onto Diagnostics and timed to the refresh. No new drawing, no dial, no 3D. It is the smallest possible answer and it does read as "something just checked" — but it says nothing about what is being checked, where the two dials do.

The read. B — sweep only while checking. It is the only one of the three whose motion is true, and this app has spent a lot of effort on not showing progress it cannot back up: the evidence gate, the unset K, the hold rate it refuses to fake. A radar that spins on an idle machine is the same category of lie, just a prettier one. A is the better-looking option and there is no hard argument against it — but it should be a choice made knowing the dial is decoration.
